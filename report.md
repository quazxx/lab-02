## 1. Цель

Сделать программу, которая читает журнал событий построчно, проверяет записи и сохраняет статистику. Большой файл не должен целиком попадать в память.

## 2. Постановка задачи

Программа называется `streamstats`. Она запускается из командной строки и читает один или несколько файлов формата CSV или JSON Lines.

У каждой записи четыре поля:

- `timestamp` - время в формате ISO 8601 с часовым поясом;
- `level` - уровень события;
- `source` - источник, непустая строка;
- `message` - текст сообщения.

В отчёте сохраняется:

- сколько всего событий;
- сколько событий каждого уровня;
- сколько событий каждого источника;
- какие источники дали больше всего ошибок;
- время первой и последней записи;
- сколько строк пришлось пропустить.

Если строка испорчена и флаг `--skip-invalid` не указан, программа останавливается и заканчивается с кодом 2. Если флаг указан, строка пропускается, а работа продолжается.

## 3. Как устроена программа

Файл проходит по цепочке:

```text
файл -> разбор строки -> проверка -> статистика -> отчёт JSON
                                                -> отчёт CSV
```

Сначала строка разбирается. Потом проверяется. Правильные события считаются. В конце из готовых итогов один раз собирается отчёт. JSON и CSV пишутся уже из этого отчёта, журнал второй раз не читается.

| Файл | Зачем нужен |
| --- | --- |
| `parsers.py` | читает CSV и JSON Lines |
| `analysis.py` | проверяет записи и считает статистику |
| `report.py` | собирает отчёт и записывает JSON и CSV |
| `cli.py` | принимает аргументы команды |
| `errors.py` | свои типы ошибок |
| `logging_setup.py` | журнал работы самой программы |
| `constants.py` | постоянные значения |
| `__main__.py` | запуск через `python -m streamstats` |
| `tests/` | тесты |

## 4. Что было важно при реализации

Файл читается по одной строке. Из-за этого программа не держит в памяти весь журнал.

Источники в отчёте сортируются по имени. Текущее время запуска в отчёт не записывается.

Повреждённая строка не молча выбрасывается. Без `--skip-invalid` программа останавливается. С этим флагом строка пропускается, а число пропусков попадает в поле `skipped_invalid`.

CSV строится из того же объекта `ReportData`, что и JSON. Числа заново не считаются.

## 5. Ошибки

Свои ошибки собраны в `errors.py` и относятся к общему типу `StreamStatsError`. В командной строке такая ошибка перехватывается, причина печатается, а программа завершается с кодом 2.

Отдельно обрабатывается неверное время в параметрах `--since` и `--until`.

## 6. Пример запуска

Команда:

```bash
python -m streamstats analyze data/events.csv --format csv --output report.json --csv-output report.csv
```

Программа пишет, что файл прочитан, и сохраняет два отчёта. Для трёх записей из примера JSON выглядит так:

```json
{
  "total_events": 3,
  "by_level": {
    "INFO": 1,
    "ERROR": 1,
    "CRITICAL": 1
  },
  "by_source": {
    "db": 2,
    "loader": 1
  },
  "top_error_sources": [
    {"source": "db", "count": 2}
  ],
  "first_timestamp": "2026-10-07T09:00:00+00:00",
  "last_timestamp": "2026-10-07T09:20:00+00:00",
  "skipped_invalid": 0
}
```

Тот же отчёт в CSV начинается так:

```csv
section,key,value
total_events,,3
level,INFO,1
level,ERROR,1
level,CRITICAL,1
source,db,2
source,loader,1
top_error_source,db,2
```

## 7. Тесты

Тесты лежат в папке `tests` и запускаются командой:

```bash
pytest
```

Проверяются разбор файлов, подсчёт статистики, командная строка и совпадение чисел в JSON и CSV.


## 8. Дополнительное задание

Сделан CSV-отчёт. Он получается из уже посчитанного `ReportData`, поэтому повторный проход по журналу не нужен. За дополнительный файл отвечает параметр `--csv-output`. Также сделаны фильтры. События можно отфильтровать до подсчёта. Параметр --level оставляет один уровень, --source — один источник, --since и --until задают промежуток времени. В отчёт попадают только подходящие записи, файл при этом читается один раз.

## 9. Вывод

Программа читает журнал построчно, проверяет записи и сохраняет статистику в JSON. Тот же результат можно записать в CSV. При ошибке в данных программа либо останавливается с кодом 2, либо пропускает плохую строку, если об этом попросили.
